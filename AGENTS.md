For every Autumn Reader UI task, use the frontend-design
and ui-ux-pro-max skills before implementing the interface.

Autumn Reader must have a recognizable editorial/vintage identity,
not a generic SaaS/dashboard aesthetic.

Preserve the existing visual identity:
- warm cream backgrounds
- burgundy/wine primary surfaces
- autumn orange accents
- editorial serif typography for prominent titles
- restrained borders
- book/editorial-inspired composition
- subtle autumn motifs
- generous whitespace

Avoid:
- generic dashboard cards
- excessive rounded rectangles
- gradients without a design reason
- glassmorphism
- excessive shadows
- oversized controls
- generic mobile-app layouts
- excessive pills
- excessive borders
- filling every empty area
- decorative elements that don't relate to books/reading
- changing established Autumn Reader colors arbitrarily

Desktop and mobile are not simply scaled versions of each other.
Design responsive compositions appropriate for each form factor.

When modifying an existing screen:
1. Inspect the existing Autumn Reader design system.
2. Identify the screen's information hierarchy.
3. Decide the visual composition before coding.
4. Preserve existing functionality.
5. Implement it.
6. Inspect the resulting UI visually.
7. Fix spacing, hierarchy, typography, responsiveness and
   inconsistencies before considering the task complete.

For Reader screens, prioritize reading area and ergonomics over
decoration.

For Library screens, prioritize book covers and organization.

For Home/Profile, prioritize presentation over controls.

Book-management controls belong primarily in Library.

Do not introduce a new visual language for each feature.
Everything should look like part of the same Autumn Reader product.
